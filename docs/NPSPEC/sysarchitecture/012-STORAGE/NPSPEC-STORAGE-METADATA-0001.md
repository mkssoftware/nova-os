# NPSPEC-STORAGE-METADATA-0001 – Nova Storage Metadata

## Status

Angenommen

## Kategorie

Storage / Metadata / Object Model / Semantic Storage

## Zweck

NovaOS definiert ein einheitliches Metadatenmodell für persistente Storage-Objekte.

```text
Storage Object
├── Payload
└── Metadata
```

Metadaten beschreiben Eigenschaften, Bedeutung, Herkunft und Beziehungen eines Objekts, ohne Bestandteil seines eigentlichen Payloads sein zu müssen.

## Grundprinzip

```text
Metadata ≠ Payload
Metadata ≠ Filename
Metadata ≠ Object Identity
```

Metadaten gehören logisch zum Objekt und sollen unabhängig von dessen Pfad verfügbar bleiben.

## Metadatenklassen

NovaOS muss mindestens folgende Klassen unterstützen können:

```text
Core Metadata
Semantic Metadata
Security Metadata
Version Metadata
Relationship Metadata
Provenance Metadata
```

Beispiele:

```text
Name
Type
Size
Timestamps
Owner
Permissions
Semantic Type
ContentID
VersionID
Tags
Relationships
```

## Speicherung

Metadaten sollen bevorzugt gemeinsam mit dem Objekt beziehungsweise innerhalb seiner nativen Storage-Struktur gespeichert werden.

```text
Object
├── Payload
└── Metadata
```

Falls ein Dateisystem bestimmte Metadaten nicht unterstützt, darf das VFS kontrollierte zusätzliche Speicherung verwenden.

```text
Native Metadata
     ↓
or
Sidecar / Metadata Store
```

Die logische Bindung an die `ObjectID` muss erhalten bleiben.

## Metadaten-Schema

Metadatenfelder sollen über stabile und versionierbare Typen definiert werden.

```text
Metadata Field
├── ID
├── Type
├── Value
└── Schema Version
```

Unbekannte erweiterte Felder sollen erhalten bleiben können, sofern sie nicht ungültig oder sicherheitskritisch sind.

## Semantic Metadata

Semantische Informationen werden über das Metadata-Modell mit Storage-Objekten verbunden.

```text
ObjectID
   ↓
Semantic Metadata
├── Semantic Type
├── Tags
└── Domain Properties
```

Dadurch können Capabilities Daten unabhängig von Dateiendungen klassifizieren und verarbeiten.

## Beziehungen

Metadaten dürfen Beziehungen zu anderen Objekten enthalten.

```text
Object A
├── references → Object B
└── derived-from → Object C
```

Solche Beziehungen sollen stabile `ObjectID`s statt Pfade verwenden.

## Versionierung

Metadaten müssen versionierbar sein können.

```text
Version 1
├── Payload A
└── Metadata A

Version 2
├── Payload A
└── Metadata B
```

Eine reine Metadatenänderung kann somit eine neue Objektversion erzeugen, ohne dass sich der Payload ändern muss.

## Sicherheit

Security-Metadaten dürfen nur durch entsprechend autorisierte Komponenten verändert werden.

Dazu gehören insbesondere:

```text
Owner
Permissions
Security Labels
Trust Information
Retention Rules
```

Normale Metadatenänderungen dürfen keine indirekte Rechteerweiterung ermöglichen.

## Provenance

NovaOS darf Herkunftsinformationen speichern.

```text
Created By
Derived From
Imported From
Generated By
Modified By
```

Provenance soll versionsbezogen sein, wenn sich die Herkunft einzelner Versionen unterscheidet.

## Suche

Metadaten sollen indexierbar sein.

```text
Metadata
   ↓
Index
   ↓
Search / Discovery
```

Dadurch können Objekte anhand ihrer Eigenschaften gefunden werden, ohne ihren Pfad zu kennen.

## Legacy-Dateisysteme

Legacy-Dateisysteme dürfen nur einen Teil des Nova-Metadatenmodells nativ unterstützen.

```text
Nova Metadata
      ↓
VFS Projection
      ↓
Legacy Filesystem
```

Nicht nativ darstellbare Metadaten dürfen über zusätzliche Storage-Mechanismen erhalten werden.

## Introspection

NovaOS soll mindestens bereitstellen können:

```text
ObjectID
Metadata Schema
Metadata Fields
Semantic Type
Version
Relationships
Provenance
Storage Method
```

Sicherheitskritische Metadaten müssen entsprechend dem Security Context gefiltert werden.

## Normative Anforderungen

1. NovaOS MUSS Metadaten logisch vom Payload eines Storage-Objekts trennen.
2. Metadaten MÜSSEN an stabile Objektidentitäten statt ausschließlich an Pfade gebunden sein.
3. Metadatenfelder SOLLEN typisiert und versionierbar sein.
4. NovaOS MUSS erweiterbare Metadaten unterstützen können.
5. Semantische Metadaten MÜSSEN in das gemeinsame Metadata-Modell integrierbar sein.
6. Objektbeziehungen SOLLEN stabile `ObjectID`s verwenden.
7. Metadaten MÜSSEN gemeinsam mit Objektversionen versionierbar sein können.
8. Security-Metadaten DÜRFEN nur autorisiert verändert werden.
9. Nicht unterstützte native Metadaten DÜRFEN über kontrollierte zusätzliche Speicherung erhalten werden.
10. Metadatenänderungen DÜRFEN keine unautorisierte Rechteerweiterung ermöglichen.
11. Metadaten SOLLEN für Suche und Discovery indexierbar sein.
12. Metadaten und ihre Herkunft SOLLEN introspektierbar sein.

## Ergebnis

```text
ObjectID
   ↓
Metadata Layer
├── Core
├── Semantic
├── Security
├── Version
├── Relationships
└── Provenance
   ↓
Storage / Search / Capabilities
```

NovaOS erhält damit ein einheitliches, erweiterbares und pfadunabhängiges Metadatenmodell als Grundlage für semantischen Storage, Versionierung, Suche und Objektbeziehungen.
