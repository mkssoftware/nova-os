---

## 1. Zusammenfassung

Dieses RFC definiert das Nova Object Model, kurz NOM.

NOM ist ein leichtgewichtiges Objektmodell für C. Es stellt gemeinsame Mechanismen für verwaltete Laufzeitentitäten bereit, ohne eine C++-Runtime vorauszusetzen.

Das Objektmodell dient unter anderem für:

- UI-Elemente
- Fenster
- Assets
- Datenträger
- Dateien
- Anwendungen
- Plugins
- Events
- Tasks
- Services

Nicht jede Struktur im System wird automatisch zu einem NovaObject.

## 2. Ziele

NOM soll folgende Eigenschaften bereitstellen:

1. eindeutige Objektidentität
2. Typinformation
3. definierter Lebenszyklus
4. einheitliche Initialisierung
5. definierte Zerstörung
6. optionale Update- und Render-Funktionen
7. spätere Referenzzählung
8. Debug- und Diagnosefähigkeit
9. Erweiterbarkeit
10. ABI-Stabilität öffentlicher Typinformationen

---

## 3. Nicht-Ziele

NOM ist ausdrücklich kein vollständiger Ersatz für C++.

NOM implementiert zunächst nicht:

- automatische Vererbung
- Templates
- Exceptions
- RTTI im C++-Sinn
- Garbage Collection
- automatische Serialisierung
- Mehrfachvererbung
- automatische virtuelle Methodentabellen

Diese Mechanismen dürfen bei Bedarf später separat ergänzt werden.

---

## 4. Was ist ein NovaObject?

Ein NovaObject ist eine verwaltete Laufzeitentität mit mindestens einem der folgenden Merkmale:

- eigene Identität
- eigener Lebenszyklus
- registrierter Typ
- Besitz von Ressourcen
- Empfang von Events
- Beteiligung an Diensten
- referenzierbarer Zustand
- registrierte Operationen

Beispiele:

- ein Fenster
- ein Button
- ein Font
- ein geöffnetes Dateiobjekt
- ein erkannter Datenträger
- eine laufende Anwendung
- ein Plugin
- ein Task

---

Einfache Werttypen werden normalerweise nicht als NovaObject modelliert.
